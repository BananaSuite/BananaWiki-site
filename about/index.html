About BananaWiki

How a wiki started at Officina Tecnologica became free software and a hosting platform.

Where it started

Luca Zani started BananaWiki on 20 February 2026 at Officina Tecnologica, which needed a wiki for its work. The first version was a small Flask and SQLite application.

Development sped up in June 2026 during an FSL placement (formazione scuola-lavoro, the Italian school work experience scheme). Since then it has grown from a wiki for one group into a platform that creates and runs a separate wiki for each customer.

It was an internal project until September 2026. It is now free software. The same code runs the hosted service, and anyone can install it on their own server.

How it grew

  1. February 2026

    Luca Zani started BananaWiki at Officina Tecnologica, with a Markdown editor with live preview, sign-in, page history and the first administration screens.

  2. April 2026

    Added the plugin system, Kanban boards and Canvas diagrams.

  3. May 2026

    Added the hosting platform, which gives each wiki its own isolated instance, and the Italian interface.

  4. June 2026

    Development sped up during the FSL placement. Text-to-speech moved to Piper voices running on the server, followed by owner controls, easy mode, developer tools and a much larger automated test suite.

  5. July 2026

    Moved to bananawiki.com, with a new hosting portal, and published the terms and privacy policy on this site. BananaAI, the chat for self-hosted models, became a separate project, now called BananaChat.

  6. August 2026

    Started work on BananaVibe (first called BananaAgent), a supervisor that keeps coding agents working on long tasks.

  7. September 2026

    BananaWiki, BananaChat and BananaVibe were published as free software under the GNU AGPL. At the end of the month, BananaWiki 1.6, a rewrite, replaced the first public release, together with a redesigned hosting portal.

  8. October 2026

    BananaWiki 1.7 added the German interface, and new server installations started updating to release tags. BananaChat 1.7 added external API providers. BananaVibe 1.0 was released as a command-line tool. BananaWiki 1.7.2 added image options to the page editor and made certificates for new hosted wikis more reliable, and BananaChat 1.7.2 added Claude Code and Codex subscription pools.

  9. November 2026

    BananaWiki 1.8 and BananaChat 1.8 simplified their settings and administration pages, and the hosting portal got a new look. BananaGit, a fork of Gitea for our Git projects, was published. The hosting account became a sign-in for the whole suite: wikis, BananaChat and BananaGit can all accept it.

The other projects

BananaChat began as BananaAI, from the wish to self-host AI models. It started inside the wiki and now runs on its own, as a way to introduce people to local AI.

BananaVibe is a command-line tool that keeps coding agents such as Claude Code, Codex or OpenCode working on a goal. Each session starts with a fresh context, and the plan and notes are kept in files and in git. When an agent says the work is done, BananaVibe runs your checks and asks an independent reviewer agent to audit it. The agents’ work is committed to a separate branch of each repository.

BananaGit is a fork of Gitea for hosting our Git projects. It keeps Gitea’s features and adds the BananaSuite look and an updater that verifies a signed release, takes a backup and rolls back on failure.

Why the public history is short

The public repositories start from a clean copy of the source code, so the development history from before the public release isn’t included.

How the hosted service is run

  • It runs the same public source code that anyone can download and install.
  • Sign-up for new users isn’t always open.
  • Each wiki runs in its own container on servers in the European Union, and the operator keeps encrypted backups.
  • There’s no advertising, and user data is never sold.
  • The privacy policy explains what we collect and why, and the terms set the rules for using the service.
