Ein Schwesterprojekt von BananaWiki

Ein Chat für deine Gruppe, mit Modellen deiner Wahl

Betreibe einen Chat für deine Gruppe auf deinem eigenen Server, mit lokalen Ollama-Modellen oder externen Anbietern wie Anthropic, OpenAI und OpenRouter. Administratoren legen fest, wer welches Modell nutzen darf und wie viel.

Funktionen

Eine Installation versorgt eine Gruppe, etwa eine Klasse, ein Labor oder ein Büro. Alle haben ein eigenes Konto, und Administratoren legen fest, welche Modelle jede Person nutzen darf und wie viel.

Chatten

  • Antworten im Stream, mit dem Gedankengang des Modells, wenn vorhanden
  • Darstellung von Markdown und Code, mit Kopieren und Herunterladen bei jedem Codeblock
  • Anhänge, darunter Bilder, PDFs, Text- und Codedateien
  • Suche, Exporte, Links zum Teilen und Chats, die nicht in deinem Verlauf landen
  • Gehostete Modelle funktionieren, wenn der lokale Modellserver ausfällt

Persönlichkeiten

  • Ein Avatar, eine Begrüßung, Gesprächseinstiege, ein bevorzugtes Modell und ein Antwortstil
  • Eine Standardpersönlichkeit für neue Chats und Vorlagen als Ausgangspunkt
  • Links zum Teilen sowie Import und Export als JSON
  • Empfohlene Persönlichkeiten, die für alle veröffentlicht werden, mit Moderation

API

  • Eine OpenAI-kompatible API: Chat Completions, die Modellliste und Bilderzeugung
  • Persönliche API-Schlüssel, nur lesend oder mit vollem Zugriff und optionalem Ablaufdatum, und ein Playground
  • Die Schlüssel eines Kontos teilen sich sein Kontingent und seine Regeln für die Anfragerate

Cloud-Sitzungen (optional)

  • Coding-Sitzungen mit einem Modell, das Werkzeuge aufrufen kann, in einer isolierten Sandbox
  • Werkzeugaufrufe und Befehlsausgaben live, und die Dateien, die das Modell ändert
  • Den Arbeitsbereich oder einen Git-Patch herunterladen oder eine weitere Anweisung senden, solange der Arbeitsbereich erhalten bleibt
  • Standardmäßig aus, und Administratoren legen fest, wer eine Sitzung starten darf. Es gelten Grenzen für Modellzugriff, Tokens, Dauer und Ressourcen

Verwaltung

  • Benutzer und Einladungen sowie Bestätigung in zwei Schritten für jedes Konto, die für Administratoren vorgeschrieben werden kann
  • Externe API-Anbieter mit verschlüsselt auf dem Server gespeicherten Schlüsseln, einem Verbindungstest und Modellen aus der eigenen Liste des Anbieters
  • Voreinstellungen für Anthropic, OpenAI, OpenRouter, Google Gemini, Mistral und andere OpenAI-kompatible Dienste sowie für lokale Server wie LM Studio, vLLM, llama.cpp und LiteLLM (es gelten die Abrechnung und die Bedingungen des jeweiligen Anbieters)
  • Pools aus Claude-Code- und Codex-Abonnementkonten, mit Nutzungsgrenzen und strikten Modellgrenzen (optional, und die gemeinsame Nutzung braucht die Zustimmung des Anbieters)
  • Zugriffsregeln pro Modell und Kategorie, Token-Kontingente pro 5 Stunden, optionale Wochenlimits und Regeln für die Anfragerate
  • Metriken, ein Audit-Protokoll, Wartungsmodus und Gestaltung

Betrieb

  • Ein Befehl installiert, aktualisiert, sichert und stellt einen Server wieder her, und die erzeugte HTTPS-Proxy-Konfiguration funktioniert auch hinter Cloudflare
  • Aktualisierungen folgen den Release-Tags, mit Abhängigkeiten, die über ihre Hashes festgelegt sind. Sie legen zuerst ein Backup an und werden zurückgerollt, wenn die neue Version nicht startet
  • Backups, auf Wunsch verschlüsselt und authentifiziert in einem privaten Git-Repository
  • Getrennte Web- und GPU-Server, freiwillige Worker-PCs und Bilderzeugung über ComfyUI
  • Helle und dunkle Designs und Leseeinstellungen für jede Person, im Kontomenü unter Darstellung

Installation

Probier es zuerst auf deinem eigenen Computer aus. Für eine Gruppe sind zwei Rechner üblich: ein GPU-Server, auf dem die Modelle laufen, und ein Webserver, der Konten und Chats speichert.

Auf deinem Computer

# Python 3.12 oder neuer, und Ollama mit einem Modell
ollama pull qwen3:4b
git clone https://github.com/BananaSuite/BananaChat.git
cd BananaChat
./dev.sh

Öffne dann http://127.0.0.1:8000. Das Terminal gibt das Token aus, mit dem du den ersten Administrator anlegst, und der Server ist nur auf deinem eigenen Rechner erreichbar.

Auf zwei Linux-Servern

# auf beiden Servern das neueste Release auschecken
git clone https://github.com/BananaSuite/BananaChat.git
cd BananaChat
git checkout "$(git tag --list 'v*' --sort=-v:refname | head -n 1)"

# auf dem GPU-Server (gibt einen Kopplungscode aus)
sudo ./banana install --mode compute --domain compute.example.org
sudo bananachat proxy --install

# auf dem Webserver
sudo ./banana install --domain chat.example.org --pair
sudo bananachat proxy --install

Nutze auf beiden Servern dasselbe Release und halte den Kopplungscode geheim. Um alles auf einem Rechner zu betreiben, nimm --mode single. Um ein bereits laufendes Ollama weiter zu nutzen, nimm --ollama-url. Die Anleitung zur Bereitstellung und die Anleitung zu Backups (auf Englisch) erklären den Rest.

Wohin die Unterhaltungen gehen

Wo werden Chats gespeichert?

Chats werden in der SQLite-Datenbank des Servers gespeichert. Lokale Ollama-Modelle laufen auf deiner eigenen Hardware, während ein Cloud-Anbieter, den du einrichtest, die Anfragen erhält und seine eigenen Datenschutzbedingungen anwendet.

Wo laufen Cloud-Sitzungen?

Werkzeuge laufen in einem isolierten Arbeitsbereich auf dem Sandbox-Runner, den der Administrator eingerichtet hat. Anweisungen, Dateiinhalte und Werkzeugergebnisse können an den gewählten Modellanbieter gesendet werden, und Administratoren können die Sitzungsprotokolle einsehen. Arbeitsbereiche laufen nach der eingestellten Aufbewahrungsfrist ab, also lade die Dateien herunter, die du behalten willst.

Welche Modelle unterstützen Cloud-Sitzungen?

Modelle, die Werkzeuge aufrufen können, über Ollama oder einen externen API-Anbieter. Cloud-Sitzungen bleiben aus, bis ein Administrator den Runner einrichtet und sie einschaltet.

Sind Chats ohne Verlauf privat?

Sie erscheinen nicht in deinem Verlauf und werden nach einer Zeit gelöscht, die der Administrator festlegt. Administratoren können sie trotzdem in einem Audit-Protokoll einsehen, und die Oberfläche weist dich darauf hin.

Wer kann Prompts lesen, wenn Worker-PCs genutzt werden?

Die Menschen, die diese Worker-PCs betreiben, können die Nachrichten, den Gesprächskontext und die Bilder lesen, die an ihre Rechner gehen. Worker-PCs sind aus, bis ein Administrator sie hinzufügt.

Was gibt ein Link zum Teilen preis?

Alle, die den Link haben, können die geteilte Unterhaltung lesen.

Wie es mit BananaWiki zusammenhängt

BananaChat begann als BananaAI, eine Möglichkeit, KI-Modelle auf eigener Hardware zu betreiben. Es entstand als Teil von BananaWiki und wurde später zu einer eigenen Anwendung.

Die beiden sind getrennte Programme mit eigenen Installationen und Konten, und BananaWiki enthält kein Sprachmodell. Luca Zani hat beide entwickelt und pflegt sie mit Mitwirkenden. Die Seite Über uns erzählt die ganze Geschichte.
