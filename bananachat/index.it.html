Una chat per il tuo gruppo, con i modelli che scegli

Gestisci una chat per il tuo gruppo sul tuo server, con modelli locali Ollama o provider esterni come Anthropic, OpenAI e OpenRouter. Gli amministratori stabiliscono chi può usare quale modello, e quanto.

Funzioni

Un’installazione serve un gruppo, come una classe, un laboratorio o un ufficio. Ognuno ha il proprio account, e gli amministratori stabiliscono quali modelli può usare ogni persona, e quanto.

Chat

  • Risposte in streaming, con il ragionamento del modello quando disponibile
  • Markdown e codice formattati, con copia e download su ogni blocco di codice
  • Allegati, tra cui immagini, PDF, file di testo e di codice
  • Ricerca, esportazioni, link di condivisione e chat escluse dalla cronologia
  • I modelli cloud funzionano quando il server locale dei modelli non è attivo

Personalità

  • Avatar, saluto, spunti di conversazione, modello preferito e stile di risposta
  • Una personalità predefinita per le nuove chat e modelli da cui partire
  • Link di condivisione e importazione ed esportazione in JSON
  • Personalità in evidenza pubblicate per tutti, con moderazione

API

  • Un’API compatibile con OpenAI: chat completions, elenco dei modelli e generazione di immagini
  • Chiavi API personali, in sola lettura o con accesso completo e una scadenza facoltativa, e un playground
  • Le chiavi di un account condividono la sua assegnazione e le sue regole di frequenza

Sessioni cloud (facoltative)

  • Sessioni di programmazione con un modello che supporta gli strumenti, in una sandbox isolata
  • Chiamate agli strumenti e risultati dei comandi in diretta, e i file modificati dal modello
  • Scarica l’ambiente di lavoro o una patch Git, oppure invia nuove istruzioni finché l’ambiente è conservato
  • Disattivate per impostazione predefinita, e gli amministratori scelgono chi può avviarne una. Valgono i limiti di accesso ai modelli, di token, di tempo e di risorse

Amministrazione

  • Utenti e inviti, e verifica in due passaggi per ogni account, che può essere resa obbligatoria per gli amministratori
  • Accesso con gli account di BananaWiki Hosting, accanto agli account locali o al loro posto (facoltativo)
  • Provider API esterni con chiavi conservate cifrate sul server, una prova della connessione e modelli scelti dall’elenco del provider
  • Configurazioni pronte per Anthropic, OpenAI, OpenRouter, Google Gemini, Mistral e altri servizi compatibili con OpenAI, e per server locali come LM Studio, vLLM, llama.cpp e LiteLLM (valgono le tariffe e le condizioni di ciascun provider)
  • Pool di account in abbonamento a Claude Code e Codex, con soglie di utilizzo e limiti rigidi per modello (facoltativi, e l’uso condiviso richiede l’approvazione del provider)
  • Regole di accesso per modello e categoria, assegnazioni di token ogni 5 ore, limiti settimanali facoltativi e regole di frequenza
  • Metriche, registro di controllo, manutenzione e temi
  • Easter egg da tastiera creati dagli amministratori, a partire dal codice Konami

Gestione

  • Un solo comando installa, aggiorna, esegue il backup e ripristina un server, e la configurazione del proxy HTTPS che genera funziona anche dietro Cloudflare
  • Gli aggiornamenti seguono i tag di rilascio, con dipendenze fissate dal loro hash. Prima fanno un backup e tornano indietro se la nuova versione non parte
  • Backup, anche cifrati e autenticati in un repository Git privato
  • Server web e server GPU separati, PC volontari e generazione di immagini con ComfyUI
  • Tema chiaro e scuro e impostazioni di lettura per ogni persona, dal menu dell’account, alla voce Aspetto

Installazione

Provalo prima sul tuo computer. Per un gruppo la configurazione tipica usa due macchine: un server GPU che esegue i modelli e un server web che conserva account e chat.

Sul tuo computer

# Python 3.12 o successivo, e Ollama con un modello
ollama pull qwen3:4b
git clone https://github.com/BananaSuite/BananaChat.git
cd BananaChat
./dev.sh

Poi apri http://127.0.0.1:8000. Il terminale stampa il token che ti serve per creare il primo amministratore, e il server è raggiungibile solo dal tuo computer.

Su due server Linux

# su entrambi i server, usa la versione più recente
git clone https://github.com/BananaSuite/BananaChat.git
cd BananaChat
git checkout "$(git tag --list 'v*' --sort=-v:refname | head -n 1)"

# sul server GPU (stampa un codice di abbinamento)
sudo ./banana install --mode compute --domain compute.example.org
sudo bananachat proxy --install

# sul server web
sudo ./banana install --domain chat.example.org --pair
sudo bananachat proxy --install

Usa la stessa versione su entrambi i server e tieni segreto il codice di abbinamento. Per mettere tutto su una sola macchina, usa --mode single. Per usare un server Ollama già in funzione, usa --ollama-url. La guida all’installazione e la guida ai backup (in inglese) coprono il resto.

Dove vanno le conversazioni

Dove sono salvate le chat?

Le chat sono salvate nel database SQLite del server. I modelli locali di Ollama girano sul tuo hardware, mentre un provider cloud che configuri riceve le richieste e applica le proprie condizioni di privacy.

Dove vengono eseguite le sessioni cloud?

Gli strumenti vengono eseguiti in un ambiente isolato sul runner sandbox configurato dall’amministratore. Istruzioni, contenuto dei file e risultati degli strumenti possono essere inviati al provider del modello scelto, e gli amministratori possono consultare i registri della sessione. Gli ambienti scadono dopo il periodo di conservazione impostato dall’amministratore, quindi scarica i file che vuoi tenere.

Quali modelli supportano le sessioni cloud?

I modelli che supportano gli strumenti, tramite Ollama o un provider API esterno. Le sessioni cloud restano disattivate finché un amministratore non configura il runner e le abilita.

Le chat escluse dalla cronologia sono private?

Non compaiono nella tua cronologia e vengono cancellate dopo un tempo scelto dall’amministratore. Gli amministratori possono comunque rivederle in un registro, e l’interfaccia te lo indica.

Chi può leggere i messaggi quando si usano i PC volontari?

Chi gestisce quei PC può leggere i messaggi, il contesto della conversazione e le immagini inviati alle sue macchine. I PC volontari non sono attivi finché un amministratore non li aggiunge.

Cosa rende visibile un link di condivisione?

Chiunque abbia il link può leggere la conversazione condivisa.

Il legame con BananaWiki

BananaChat è nato come BananaAI, un modo per far girare i modelli di intelligenza artificiale sul proprio hardware. È partito come parte di BananaWiki ed è poi diventato un’applicazione separata.

Sono due programmi distinti, con installazioni separate, e BananaWiki non include un modello linguistico. Anche gli account sono separati, a meno che un amministratore non faccia accedere a BananaChat con un account BananaWiki Hosting. Luca Zani li ha creati entrambi e li mantiene con i collaboratori.
