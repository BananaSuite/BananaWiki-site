A sister project of BananaWiki

Gitea for your projects, with an updater that rolls back

BananaGit is a self-hosted Git service with repository hosting, code review, issues, a package registry and CI/CD. It’s a fork of Gitea in the BananaSuite colours, and its updater checks a signed release, takes a backup and rolls back if the new version doesn’t start.

Install

Try it on your own computer first. A server needs Linux on amd64 or arm64 with systemd, Git, a PostgreSQL database and Python 3.9 or newer for the updater.

On your computer

# Git, Go and Node.js with pnpm
git clone https://github.com/BananaSuite/BananaGit.git
cd BananaGit
TAGS="sqlite sqlite_unlock_notify" make build
./gitea web

Then open http://localhost:3000, keep SQLite as the database and register. The first account is the administrator, and everything stays in that folder.

On a Linux server

# after the README’s install steps
sudo bananagit-update check
sudo bananagit-update update

The README sets up the user, the directories, the release binary and the service. The updating guide covers every setting and what to do when an update fails. For other setups, follow Gitea’s installation guide with the BananaGit binary. Coming from Gitea, you swap the binary and keep your database and data, as the migration guide explains.

How it relates to BananaWiki

We made BananaGit to host our own Git projects. It uses the same banana logo as BananaWiki and BananaChat, and it’s installed separately from both.

Changes that aren’t about BananaGit’s name, look or updater belong in Gitea. The About page tells the story of the other projects.
